# Linuxの「パス」と「環境変数」は何で、コマンドを実行するときにどう関係しますか？

## 一言でいうと

パスは「ファイルやコマンドがどこにあるか」を表す住所です。環境変数は、シェルやプログラムに渡される設定値です。

この2つは別物ですが、よく一緒に出てきます。特に `PATH` という環境変数は、コマンド名だけを入力したときに、Linux がどの場所を探すかを決めます。

## 何がうれしいのか

たとえば `python` や `node` と入力したとき、毎回 `/usr/bin/python` のような完全な場所を書かなくても実行できます。これは `PATH` に「探してよい場所の一覧」が入っているからです。

環境変数は他にもあります。たとえば `HOME` は自分のホームディレクトリ、`LANG` は言語設定、`EDITOR` は標準で使うエディタを表すことがあります。

## どう考えると理解しやすいか

Linux でコマンドを実行するときは、次の順で考えると整理しやすいです。

1. 入力したものがファイル名か、コマンド名かを見る。
2. `/` や `./` を含むなら、その場所を直接見に行く。
3. コマンド名だけなら、`PATH` に並んだディレクトリを順番に探す。

つまり `PATH` は「コマンド検索用の地図」です。環境変数全体は「プログラムに渡される設定のメモ」と考えると近いです。

## 具体例

`echo $PATH` とすると、`PATH` の中身を確認できます。

```bash
echo $PATH
```

多くの場合、次のように複数のディレクトリが `:` で区切られています。

```text
/usr/local/bin:/usr/bin:/bin
```

この状態で `git` と入力すると、シェルは `/usr/local/bin/git`、`/usr/bin/git`、`/bin/git` のように順番に探します。見つかった最初のものが実行されます。

## 関連用語

- 絶対パス: `/home/user/file.txt` のように、ルートから始まる場所。
- 相対パス: `./file.txt` や `../memo.txt` のように、今いる場所から見た場所。
- シェル: コマンド入力を受け取り、プログラムを起動するもの。
- 環境変数: プログラムが参照できる設定値。

## 次に知るとよいこと

次は `which` と `env` を調べると理解が進みます。`which git` は実際にどの `git` が使われるかを確認するコマンドです。`env` は現在の環境変数を一覧できます。
